\# SQL 数据分析 Agent 项目复盘



\## 项目目标



构建一个可以把自然语言业务问题转换为 SQL，并安全查询数据库的完整应用。



项目不仅需要查询成功，还需要解决危险 SQL、权限控制、失败重试、评测、前端和部署问题。



\## 已完成能力



\- 创建 SQLite 示例业务数据库

\- 实现自然语言问题到 SQL 的规则转换

\- 返回 SQL、查询解释和结构化结果

\- 提供 FastAPI `/health` 和 `/ask`

\- 提供 Streamlit 表格与图表页面

\- 只允许单条 SELECT 查询

\- 拦截危险 SQL 关键字

\- 使用 SQLite Authorizer 实现表和字段白名单

\- SQL 失败后最多修复一次

\- 记录综合评测 JSONL 日志

\- 完成 Docker 构建、运行和健康检查



\## 关键技术决策



\### 为什么先使用规则生成 SQL



规则方式结果稳定、可解释，适合先验证 SQL Agent 的完整工程链路。



它的限制是泛化能力较弱，因此 README 和演示中明确说明当前没有接入真实大模型，避免夸大项目能力。



\### 为什么使用 SQLite Authorizer



只检查 SQL 字符串不能完整处理子查询、别名等情况。



SQLite Authorizer 会在数据库实际读取表和字段时检查权限，因此比简单字符串匹配更可靠。



\### 为什么只修复一次



无限重试会增加延迟和资源消耗，也可能让错误 SQL 反复执行。



系统第一次执行失败后只允许进行一次确定性修复，第二次仍失败就立即停止。



\### 为什么数据库不提交 Git



`sales.db` 是可以由脚本重新生成的运行产物。仓库只保留数据库初始化脚本，保证数据结构可复现，同时避免提交二进制文件。



\## 遇到的问题



\### PowerShell 中文显示乱码



API 能正确识别中文问题并返回查询结果，乱码只发生在 PowerShell 对对象的显示环节，不属于 API 编码错误。



前端和 JSON 数据本身保持正常。



\### Docker 找不到 Dockerfile



记事本把文件保存成了 `Dockerfile.txt`。将文件重命名为没有扩展名的 `Dockerfile` 后构建成功。



\### Docker 端口冲突



本地 API 使用 `8003`，Docker 容器映射到主机 `8004`，两套服务可以同时运行。

\## 60 秒面试讲解



我完成了一个 SQL 数据分析 Agent。用户输入自然语言业务问题后，系统会生成 SQL，查询 SQLite，并通过 FastAPI 和 Streamlit 返回 SQL、解释、表格和图表。



项目的重点是 SQL 安全。我限制系统只能执行单条 SELECT，并拦截 DELETE、DROP 等危险操作。同时使用 SQLite Authorizer 实现表和字段白名单，避免访问系统表或未授权字段。



对于执行失败的 SQL，我实现了最多一次的确定性修复，修复后仍失败就停止，避免无限重试。



我还建立了综合评测，统计 SQL 执行成功率、危险 SQL 拦截率、结果解释可用率和响应时间，并完成了 Docker 部署与健康检查。



当前自然语言转 SQL 使用规则实现。后续可以接入大模型和 Schema Prompt，提高问题覆盖范围。
