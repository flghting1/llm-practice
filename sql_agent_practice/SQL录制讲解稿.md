# SQL 数据分析 Agent 录制讲解稿

## 录制目标

录制一段 2 分 30 秒到 3 分钟的项目演示，说明自然语言查询、受控 SQL 执行、权限边界和固定评测。当前实现是规则型自然语言转 SQL 原型，不将其表述为可自主处理任意数据库问题的大模型 Agent。

## 3 分钟讲解与操作

### 0:00 - 0:20 项目定位

屏幕：项目首页，保留左侧“执行边界”和“固定回归集”。

讲解：

> 这是我完成的受控 SQL 数据分析应用，面向销售、客户和订单分析。业务人员可以用自然语言提出问题，但系统只允许只读查询，权限和执行边界不交给上层自然语言模块决定。

### 0:20 - 1:10 正常查询

屏幕操作：输入 `各商品的销售额是多少？`，点击“生成受控查询”。停留在查询结果、生成 SQL、表格和柱状图。

讲解：

> 这里我查询各商品的销售额。当前版本用规则将四类已定义业务问题转换为 SQL，再调用 FastAPI 进入执行层。页面保留了生成的 SQL、返回记录和图表，方便用户核对查询依据。这个问题只执行了一次，返回三条商品销售额记录。

### 1:10 - 1:50 安全边界

屏幕：左侧“SELECT ONLY”“100 ROWS”“MAX 1”，随后切换到本地终端运行权限或安全测试。

讲解：

> 项目的重点是执行层安全，而不是让模型直接获得数据库权限。执行层只接受单条 SELECT，危险的增删改语句会被拦截；SQLite Authorizer 再限制允许访问的表和字段，系统表和未授权字段也无法读取。结果最多返回一百行，SQL 失败时只允许一次确定性修复，避免无限重试。

### 1:50 - 2:25 固定评测

屏幕操作：运行 `test_sql_agent_safety.py`、`test_sql_permissions.py` 或 `evaluate_sql_agent_metrics.py`，停在汇总结果。

讲解：

> 我用固定用例覆盖四个正常业务问题、四条危险 SQL、两个无效问题和一次失败 SQL 识别。当前固定集的成功、拦截、解释和拒绝指标均为一百百分比，但这只说明当前小型 SQLite 示例数据和预设场景的回归测试通过，不能代表生产泛化能力。

### 2:25 - 2:55 限制与扩展

屏幕：README 的“当前限制”章节。

讲解：

> 当前限制是自然语言转 SQL 为规则实现，只覆盖四类问题，使用本地 SQLite 数据，也没有认证和多租户。后续接入真实模型时，模型只负责生成 SQL 草案；单语句检查、只读限制、表字段白名单、行数上限和数据库 Authorizer 都要保留在执行层。

## 录制验收

- 时长控制在 2 分 30 秒到 3 分 30 秒。
- 至少出现一次正常查询、生成 SQL、数据表和图表。
- 至少展示一次危险 SQL 或未授权字段被拒绝。
- 只说“固定评测集 100%”，不说“100% 准确”或“生产级 Agent”。
- 视频中不出现终端账号、浏览器通知、聊天消息或个人信息。
