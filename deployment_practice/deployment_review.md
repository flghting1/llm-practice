\# 统一部署链路复盘



\## 项目目标



将三个独立 AI 项目整理为一条可重复执行的本地 Docker 部署链路，实现构建、启动、健康检查、核心接口验收和停止清理。



\## 已完成能力



\- 部署前关键文件检查

\- 三个项目统一 Docker 构建

\- 自动清理旧容器

\- 固定端口启动三个服务

\- 健康检查轮询

\- 核心业务接口验收

\- 响应时间记录

\- JSONL 部署日志

\- 统一停止和清理容器



\## 关键问题与解决方式



\### RAG 容器无法启动



原因是容器内没有 Embedding 模型缓存，并且无法连接 Hugging Face。



解决方式是把 Windows 本地 Hugging Face 缓存只读挂载到容器，并开启离线模式。



\### RAG 没有 healthy 状态



原因是原 Dockerfile 未配置 `HEALTHCHECK`。



补充健康检查后，RAG、SQL Agent 和简历匹配三个容器都能显示 `healthy`。



\### PowerShell 中文乱码



Windows PowerShell 5.1 读取无 BOM UTF-8 脚本时可能显示乱码。



部署脚本的运行逻辑不受影响，后续输出尽量使用英文状态信息，业务 JSON 使用 UTF-8 字节发送。



\## 当前结果



\- 三个服务健康检查通过

\- 三个核心业务接口通过

\- 统一部署验收通过率：100%

\- RAG 可以在断网情况下使用本地模型缓存启动



\## 面试讲解



我为三个 AI 项目补充了一条统一 Docker 部署链路。脚本会检查项目文件、构建镜像、清理旧容器、启动服务并轮询健康接口。



部署完成后，另一个验收脚本会调用三个项目的核心业务接口，检查返回字段并记录响应时间。



其中 RAG 容器启动时遇到了 Hugging Face 网络不可用的问题。我通过只读挂载本地模型缓存和设置离线环境变量解决，并为三个项目统一加入 Docker 健康检查。



当前链路用于本地可复现部署，后续可以扩展到 GitHub Actions 和云服务器。
